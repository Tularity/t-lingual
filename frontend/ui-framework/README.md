# @t-lingual/ui

The component framework behind t-lingual. It is a **framework layer**: it knows
about buttons, dialogs, tables and focus management, and nothing about
interpretation sessions, passkeys, the API client, or routing. Feature code
consumes it; it never reaches back.

49 components, 3 primitives, 7 hooks, a two-tier token system, and the Tularity
mark as a component, in ~37 kB of JavaScript and ~20 kB of CSS gzipped.

## Using it

```tsx
import { ThemeProvider, ToastProvider, Button, Dialog, DialogTitle } from '@t-lingual/ui'

<ThemeProvider>
  <ToastProvider>
    <App />
  </ToastProvider>
</ThemeProvider>
```

Add `className="tl-root"` to `<body>` or a wrapper to opt the document into the
framework's typography, background and scrollbar treatment. The package does not
restyle the host document on import — a library that does that cannot be adopted
one screen at a time.

To avoid a flash of the wrong theme on load, render `themeInitScript()` in
`<head>` with `dangerouslySetInnerHTML`. It applies `data-theme` during parse,
before first paint.

## Layers

```
styles/       cascade layers, reset, tokens, base
utils/        cx
hooks/        useControllableState, useEventCallback, useMediaQuery,
              useReducedMotion, useScrollLock, useDismiss, useFocusTrap
primitives/   Slot + Slottable (asChild), VisuallyHidden, Portal
providers/    ThemeProvider
icons/        Icon — one outline set on a 24×24 grid
components/   one directory each, co-located CSS; CompactMark and
              CollapseMark are the logo's two animated forms
index.ts      the only public surface, generated by tools/gen-index.mjs
```

## Tokens

Two tiers. Tier 1 (`--tl-sand-500`, `--tl-amber-500`) is raw values and is
**never referenced from a component**. Tier 2 names a role — `--tl-text-secondary`,
`--tl-danger-border`, `--tl-focus-ring` — and is all a component may use. Moving
the accent off amber is then a change to one file rather than an archaeology
exercise.

Colour is authored in OKLCH because it is perceptually uniform: step 500 of every
hue reads at the same lightness, so a status colour can be swapped without
silently changing which text passes contrast on top of it. The ramps are derived
from t-lingual's established yellow/brown identity, and every legacy hex still
lands on a step.

Dark theme lives entirely in tier 2 under `[data-theme='dark']`. A component that
needs a `[data-theme]` block of its own is a component missing a semantic token.

## Motion

One signature curve — `cubic-bezier(0.16, 1, 0.3, 1)`, an expo-out that covers
80% of its distance in the first third — and one rule: opacity always finishes
before transform, so a surface reads as present while it is still settling. The
rule is structural: components use the paired recipes
`--tl-transition-overlay-enter/-exit` (470 / 250 ms, Dialog and Drawer) and
`--tl-transition-popover-enter/-exit` (250 / 150 ms, Popover, Menu, Tooltip,
Toast) rather than spelling out durations, and exits mirror entrances on the same
curve. Springs are `linear()` curves sampled from the damped-oscillator solution,
not guessed control points.

A Dialog grows out of the control that opened it: pass `originRef` (or an
explicit `origin` point) and the panel starts at 15% scale on that control,
travels to the centre, and collapses back to the same frozen point on close.

A whole screen changing hands can go through an iris instead: `iris()` cuts a
round, soft-edged opening into a cover laid over the page and moves its radius
through timed stops, each on its own curve — widening to uncover what lies
beneath from a point, narrowing to close the page onto one. `irisTransition()`
swaps the page itself (a new colour theme, say) as a view transition, the new
state opening from the point over the old; without view transitions, or under
reduced motion, the update simply happens.

Overlays stay mounted through their exit. `usePresence` renders them with
`data-state="entering" | "entered" | "exiting"`, `@starting-style` supplies the
from-values, and the node is removed only when `getAnimations()` reports the real
transitions finished — durations live in CSS alone.

Reduced motion is three numbers, not a per-component media query:
`--tl-motion-scale` halves durations, `--tl-motion-distance` and
`--tl-motion-zoom` zero the travel and the zoom. Fades survive; parallax does not.
Loops never read the scale (halving a period doubles the rate) — they either keep
their own tempo because the motion is the message, or are not declared under the
preference at all.

## The marks

The static logo is not a component. It is one SVG file the product ships (the
app's `public/brand/tularity.svg`, also its favicon), framed on the centre of its
body square rather than of everything it draws, and wherever the static logo
appears it is that file. The framework carries the logo's two animated forms,
both in its fixed tonal inks `--tl-logo-solid`, `--tl-logo-base` and
`--tl-logo-light`:

- `CompactMark` is the logo redrawn for small sizes: upright, on a 4×4 or 5×5
  lattice, without the tail. Its `wave` loop keeps the mark recognisable in
  every frame — a ripple across the cells, a beat of rest, one whole turn — so
  it can run inside controls. `Spinner` is the compact mark in `inherit` tone,
  so every busy state in the product is the brand.
- `CollapseMark` is the large animation, for a screen where the logo is all
  there is, such as a first load: the pieces assemble, then the body collapses
  cell by cell from its upper-right corner and drifts off. It is drawn to a
  canvas owned by a worker, in the same frame as the static file; pass the
  static logo as `still` for reduced motion. With `linger` — from the start,
  or from the moment a function says so — the cells stay behind as dots
  instead, and `gatherTo` then draws them into a static logo elsewhere on the
  page — for a screen handing over to the one that logo is on.

## Overriding

Everything ships inside `@layer tl.components`. Unlayered CSS beats layered CSS
regardless of specificity, so an app's own rule wins with no `!important` and no
selector escalation:

```css
.my-toolbar .tl-button { border-radius: 0; }
```

Per-instance retheming goes through each component's private custom properties,
which are the styling contract:

```css
.danger-zone .tl-button { --_bg: var(--tl-danger-solid); --_fg: var(--tl-danger-on); }
```

## Accessibility

Correct roles, keyboard interaction per the WAI-ARIA Authoring Practices, one
shared focus ring, and `forced-colors` handling wherever state rides on
`background-color`. Components report a `console.error` in development when a
required accessible name is missing rather than shipping an unlabelled control.

Colour is never the only carrier of meaning: a failed step draws a warning glyph,
a switch moves its thumb, a status badge says the status in words.

Two decisions worth knowing because they look like bugs:

`Button loading` does not set `disabled`. A disabled element leaves the tab order,
so a keyboard user who presses a button and has focus destroyed under them is
returned to the top of the document with no indication of what happened. The
button stays focusable, reports `aria-busy`, and refuses activation.

Overlays mark the rest of the document `inert`, not just trap Tab. A focus trap
covers the keyboard; it does nothing for a screen reader's virtual cursor, which
moves through the accessibility tree and would otherwise walk out of the dialog
into controls that are visually behind a scrim and functionally unreachable.

## Scripts

```
npm run build --workspace=@t-lingual/ui   # library + .d.ts
npm run typecheck --workspace=@t-lingual/ui
node tools/gen-index.mjs                  # regenerate the public barrel
```

`index.ts` is generated. Add a component directory, re-run the generator, and its
values and prop types are exported — a hand-maintained barrel drifts, and the
first symptom is a consumer unable to type a wrapper without a deep import.
